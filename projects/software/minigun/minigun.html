Commands
minigun build
Build

Unity-build compilation. Configure once, run always. Clean diagnostic output, build history in the database.

minigun preprocess
Preprocess

String-to-hash replacement, reflection struct codegen. Idempotent, hash-gated, source-modifying passes.

minigun cook
Asset Cook

Walk asset directories, pack into a binary amalgamation, emit a typed C header. Deterministic output.

minigun fmt
Format

Hardwired C style. No configuration debates. Check mode or fix mode. Linting rules included.

minigun tags
Tags

Track TODO, FIXME, HACK, and custom markers. Write back creation date and author. Report on backlog.

minigun metrics
Metrics

Build history, file growth, routine churn. Query the database, generate reports, pipe to anything.

minigun script
Script

Extend minigun with .c scripts compiled in-process via libtcc. Full access to the database and config API.

minigun --init
Init

Generate a fully commented minigun.ini. Configuration as documentation — everything where you need it.

Configuration

A single minigun.ini at your project root. Generated on first run, fully commented. No back-and-forth with the manual — the useful information lives exactly where it is needed.

; minigun.ini — generated by minigun --init [project] ; Project name, used in reports and generated file headers. name = myproject ; Default author for tag annotations. Override via MINIGUN_AUTHOR. author = stephane [build] ; Minigun adds no implicit flags — what you write is what gets passed. compiler = clang c_flags = -O2 -Wall -std=c11 output_dir = build [tags] ; If true, writes creation date and author back into the source comment. types = TODO FIXME HACK NOTE REFERENCE annotate = true
Principles
01
Rebuild everything. Always.

No incremental compilation graph. No dependency tracking. Unity build by default. Simple to reason about, fast enough for the projects that matter.

02
Your codebase has memory.

Every build, every tag, every routine change is recorded in SQLite. Minigun turns your project history into something you can query.

03
One binary, zero dependencies.

No runtime, no interpreter, no package manager. Drop it in your path and run it. libcrayfish handles the platform; minigun handles the rest.

04
Extend in C, not config.

When hardwired behaviour isn't enough, write a .c script. libtcc compiles it in-process. No DSL to learn — just C.

Stack
C11 implementation language — no C++, no exceptions, no runtime
libcrayfish stdlib replacement and platform abstraction layer
SQLite vendored via libcrayfish — all persistent state, queryable
libtcc vendored via libcrayfish — in-process C compilation for scripts
.minigun/ hidden project directory — database, config cache, temp files
